# Лад — бюджет с Supabase

Рабочая версия: https://webforgeai88.github.io/family-budget-app/

Отдельное демо без регистрации: https://webforgeai88.github.io/family-budget-demo/

## Что работает

Вход и регистрация по почте и паролю через Supabase Auth. У каждого аккаунта отдельный бюджет, доступный с разных устройств. Категории, доходы, расходы, фильтры, графики, CSV, JSON-экспорт и восстановление. ИИ не подключён, запросов к платным моделям нет.

Фронтенд — React, TypeScript и Vite, опубликован на GitHub Pages. База — PostgreSQL в Supabase, проект zebfhjqepuktbrqohkmx. Таблицы lad_budgets, lad_categories, lad_operations, lad_backups. На всех таблицах включён RLS по auth.uid(). Публичный publishable key предназначен для браузера; секретных административных ключей в проекте нет.

Суммы хранятся целыми копейками. SQL-проверки типов, сумм, дат и связей работают независимо от браузерных форм. Сохранение через RPC атомарно: повреждённый импорт не удаляет прежние данные. Проверка revision защищает от перезаписи при одновременной работе. Учебный лимит: 200 категорий, 5000 операций, JSON до 5 МБ.

Перед первым изменением за день по московскому времени создаётся снимок, сохраняются последние 30 дней с изменениями. Это прикладные снимки бюджета, а не независимый бэкап всего сервиса. Копии можно скачать отдельно.

## Настройка почты владельцем

В Supabase → Authentication → URL Configuration:

- Site URL: https://webforgeai88.github.io/family-budget-app/
- Redirect URLs: тот же полный адрес с завершающим слешем.

Для подтверждения регистрации и восстановления пароля нужен работающий почтовый канал. Встроенная отправка Supabase предназначена для тестов и ограничена адресами команды проекта. Для регистрации других людей настройте Custom SMTP в Authentication. Подтверждение почты приложение не отключает. Проверить доступность SMTP и доставку письма на реальную почту владельца необходимо отдельно; тестовые подтверждённые аккаунты проверяют вход, но не доставку.

Документация: https://supabase.com/docs/guides/auth/auth-smtp

## Перенос старых записей

Старую версию и демо не изменяем. В демо откройте Категории → Резервные копии → Скачать текущий бюджет. В новой версии войдите в свой аккаунт, откройте такой же раздел и выберите JSON. Восстановление заменяет текущие категории и операции после подтверждения. Диалоги с ИИ не импортируются: консультант отключён. Новые аккаунты получают только категории, без вымышленных операций.

## Разработка

Node.js 24:

```sh
npm ci
npm test
npm run build
npm run dev
```

Миграции лежат в supabase/migrations и уже применены к указанному проекту. Не запускайте их повторно в той же базе. Изменения main публикуются workflow GitHub Actions.

## Проверки

Чистые расчёты и изменения бюджета: npm test. Реальные Auth/RLS/транзакции: tests/cloud.mjs. Браузерные формы и адаптивность на 390, 768, 1024, 1366, 1920, 2560: tests/browser.mjs. Интеграционные проверки требуют двух специально созданных временных пользователей; qa/credentials.json исключён из Git. Не используйте для них аккаунты клиентов.
